# 生物育种文献知识提取 JSONL 字段规范（v1.0.0）

> 面向“生物育种智能化”三大研究内容的育种文献解析/知识抽取/数据集构建标准 JSONL 字段体系。
> 本规范以**研究内容一（场景·知识·数据汇聚治理）**为核心任务落地，深度前置兼容研究内容二（育种科学智能体）、研究内容三（育种模型工具技能化）。

---

## 一、设计总览

### 1.1 目标
将生物育种领域**中英文科研文献**（期刊论文、学位论文、实验报告、综述、专利等）经全自动解析与知识抽取后，转换为**单一文档一行的 JSONL 记录**，实现：

- **可追溯**：每条字段关联源文位置（段落/表/图），全链路溯源；
- **可演化**：带版本、更新链、冲突消解记录，支撑知识库动态更新；
- **AI-Ready**：字段按模型输入输出、智能体状态、工具参数语义切分，可直接喂给模型训练、知识图谱构建、智能体链路与工具编排。

### 1.2 顶层结构（8 大维度 = 12 个顶层块）
每条 JSONL 记录为 1 个 JSON 对象，含 12 个顶层块，覆盖要求的八大维度：

| # | 顶层块 | 对应维度 | 内容 |
|---|--------|----------|------|
| 1 | `record_info` | 记录标识（核心基础） | 记录唯一 ID、Schema 版本、文献类型、语言、时间戳 |
| 2 | `doc_meta` | 基础文献元数据 | 题名、作者、机构、期刊、DOI、摘要、关键词、正文分段索引 |
| 3 | `breed_entities` | 育种实体数据 | 基因/性状/种质/品种/群体/环境/分子标记/QTL/病虫害等全类实体 |
| 4 | `relations` | 实体关系数据 | 基因-性状、QTL-标记、种质-基因、G×E、系谱等本体关系 |
| 5 | `experiments` | 实验过程数据 | 田间/温室/分子育种等实验设计、处理、测定、步骤 |
| 6 | `analyses` | 分析方法数据 | GWAS/QTL/基因组预测/群体遗传等模型、软件、参数、输入输出 |
| 7 | `conclusions` | 科研结论数据 | 结论声明、证据链、置信度、育种建议、可证伪性 |
| 8 | `pipeline` | 上下游任务关联 | 上下游引用、本体映射、知识图谱节点、融合状态、更新链 |
| 9 | `governance` | 知识治理字段 | 知识单元、策展状态、领域标签、质量分级、保留与访问策略 |
| 10 | `provenance` | 数据质量溯源 | 抽取引擎、源文定位、字段级置信度、质量评分、冲突、更正、文件哈希 |
| 11 | `agent` | 智能体关联字段 | 状态、假设、因果模型、推理、规划、分层记忆、工具调用、反馈闭环 |
| 12 | `skill` | 模型工具技能化字段 | 实验卡/分析卡/假设卡、工作流编排、工具绑定、I/O 适配、模型画像、可视化规范 |

### 1.3 五类字段体系
每个字段除隶属上述维度外，归属以下**五大类**之一，在字段字典中以`类别`列标注：

| 类别 | 代码 | 定位 | 主要承载块 | 服务研究内容 |
|------|------|------|-----------|--------------|
| **核心基础字段** | `C1` | 文献知识内容本体（可抽取、可入库的最小知识单元） | record_info / doc_meta / breed_entities / relations / experiments / analyses / conclusions | 研究一 |
| **知识治理字段** | `C2` | 本体对齐、实体规范、知识融合、版本、演化 | governance / pipeline(融合、更新链) | 研究一 |
| **智能体关联字段** | `C3` | 智能体状态、假设、因果、记忆、规划、工具调用闭环 | agent | 研究二 |
| **模型工具技能化字段** | `C4` | 工具封装、卡片流转、流程编排、I/O 与参数语义 | skill | 研究三 |
| **溯源质量字段** | `C5` | 溯源、质量、可信度、更正、校验 | provenance（含 entities/relations 内嵌的 confidence、evidence_spans） | 研究一（数据治理底座） |

### 1.4 三研究内容适配矩阵

| 字段来源 | 研究一 数据底座 | 研究二 科学智能体 | 研究三 技能化 |
|----------|----------------|------------------|----------------|
| `doc_meta` / `breed_entities` / `relations` | 本体实例化、实体对齐、知识库入库 | 知识状态（语义记忆）、检索依据 | 任务卡命中、输入材料 |
| `experiments` | 实验本体、元数据规范 | 规划的任务分解模板、模板记忆 | `experiment_card` 源头 |
| `analyses` | 方法有效本体、参数治理 | 方案生成、工具调用依据 | `analysis_card`、`tool_binding`、模型画像 |
| `conclusions` | 知识融合（跨文献聚合/冲突消解） | 假设生成与因果推断输入 | 假设卡、结果解释文本 |
| `pipeline` / `governance` | 图谱节点、版本、演化 | 记忆检索索引 | 流程版本、接口版本 |
| `provenance` | 数据质量评价、可信标签 | 推理置信度加权 | 结果可信度回传 |
| `agent` | 抽取出的知识反哺状态 | ✔ 推理/规划/记忆/执行 | 向工具层下发调用 |
| `skill` | 结构化卡片沉淀 | 工具调用后的结果反馈 | ✔ 封装/编排/可视化 |

## 二、落地工作流（文献 → 结构化数据 → 下游）

```
① 文献采集            ② 文档解析            ③ 知识抽取          ④ 质量校验
期刊/学位/报告/综述   PDF→XML/TEI→段落/表/图  实体/关系/实验/分析/  完整度/一致度/冲突/
→ 归一化元数据        分块并按 section_id 索引    结论/假设/卡片/画像    字段级置信度回标
        |                    |                     |                   |
        v                    v                     v                   v
⑤ 本体对齐与融合       ⑥ 知识库入库            ⑦ 下游消费
实体→本体概念ID         图谱节点/关系边          R2 智能体状态/推理/规划
同实异名合并            版本化记录                R3 卡片流转/工具编排/模型输入输出
冲突消解                更新链/演化历史            R1 知识检索/回馈治理闭环
```

**必填验证**：`record_info` 全部字段、`doc_meta.title/doi_or_source`、`breed_entities` 至少一个批次块、`relations/experiments/analyses/conclusions` 无数据时填空数组（缺省自解释），`provenance` 为必填块。详见表单字段字典中的“必填”列。

## 四、扩展与维护约定

- **版本策略**：`schema_version` 采用语义化版本 `v<major>.<minor>.<patch>`；新增字段＝minor，破坏性结构调整＝major。
- **扩展点**：`breed_entities.other_entities`、`entity_attributes`、`relations.evidence` 为开放扩展区；新物种/新方法优先走 `other_entities`/`analyses` 扩展而非新顶层块。
- **关联规范**：本体 ID（基因/性状/环境/实验方法）优先复用 TO/PO/GRO/NCBITaxon/STO 等公开本体与 ICDDD 合作本体，`ontology_id` 字段保证可回指。
- **AI-Ready 校验**：入库前对每条记录执行 `schema validate`（对应 JSON Schema）+ 必填检查 + 实体 ID 引用完整性检查（`relations`/`experiments` 引用的实体 ID 必须在 `breed_entities` 中存在）。

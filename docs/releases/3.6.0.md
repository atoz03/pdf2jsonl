# 育种文献记录契约 3.6.0 更新说明

**发布日期：** 2026-10-19　|　**版本号：** 3.6.0（MINOR）　|　**契约：** breeding-literature-record　|　**仓库：** atoz03/pdf2jsonl

本次更新为契约引入**关系的语义性质**这一层数据：区分一条关系断言的是**因果**还是**相关**。这是 3.6.0 的主线，同时看板新增「关系」页签并把所有长页签改为分页。字段由 412 增至 **414**（`transform` 50→52），规则由 35 增至 **37**（R036、R037），歧义增至 **AMB-001…042**。

3.6.0 之前产出的记录继续按其自身声明的版本通过校验。

---

## 1. 背景 / 动机

契约把关系表达为主语–谓语–宾语，但**没有说明这个谓语断言了什么**。三个问题混在一起、无法区分：

1. **谓词本身断言的是因果还是相关。** `predicate_label` 是一张开放的中文关系名列表，规范化名称看不出性质。
2. **支持关系的证据到了哪一级。** `transform.relation_evidence_type` 回答的是**依据类型**，不是强度阶梯。
3. **原文用什么语气说。** `transform.predicate_mention` 只存逐字词语，未标注是断言还是限定。

真正画这条线的两个字段——`agent.causal_direction`、`agent.association_vs_causation`——可用性为 **I**、取值未定义（**AMB-024**），抽取画像不暴露，**抽取阶段根本看不到**。于是模型可以把「关联」写成一句平铺的直接结论，下游无法据此判断能否用这条关系设计干预实验。

**只有因果关系才能直接指导实验。** 一条被写成平铺结论的「相关」，会悄悄授权一个它并不支持的实验。文献本身已包含大量因果表达（`regulates`、`decreased the`…），所以这条线应当在**抽取阶段**就建出来，而不是留给下游猜。这正是悬而未决的歧义 **AMB-042** 的落点。

## 2. 变更内容

### 2.1 三层语义：性质 / 语气 / 证据强度

3.6.0 把关系性质写成数据，分**三层、互不替代**：

| 层 | 回答的问题 | 字段 | 可用性 | 来源 |
| --- | --- | --- | --- | --- |
| **谓词性质** | 这条边断言因果、相关还是结构？ | `transform.relation_nature` | **N** | 编译期从谓词词表派生，**不由模型判断** |
| **原文语气** | 原文是说死了还是留了口？ | `transform.relation_assertion_mode` | **D** | 原文措辞 |
| **证据强度** | 证据到了哪一级？ | `transform.relation_evidence_type` | **I** | 沿用（AMB-040 的七个代码即强度阶梯） |

语义要点：**性质属于谓词本身，不属于证据强弱**。一个 `associational` 谓词即使有功能验证级别的证据，**仍然只是相关**；一个 `causal` 谓词也可能只有统计证据。

### 2.2 `predicate_label` 的每个取值带 `nature`

谓词词表的每个取值新增属性 `nature`，枚举 `causal` / `associational` / `structural` / `descriptive` / `unknown`。该属性在**契约编译期**映射为 `contract["relation_natures"]`，并由填充规则 **`relation_nature_from_predicate`**（`pdf_extraction` 的 normalizer）派生 `transform.relation_nature`。

即：性质来自**契约**，而不是对记录的二次解读。`nature` 各值与 `cues` 一样，均为仓库拟定。

### 2.3 两个新词表

| 词表 | 强制 | 封闭性 | 取值 |
| --- | --- | --- | --- |
| [`vocabularies/relation_nature.yaml`](vocabularies/relation_nature.yaml) | warning | closed | `causal` / `associational` / `structural` / `descriptive` / `unknown` |
| [`vocabularies/relation_assertion_mode.yaml`](vocabularies/relation_assertion_mode.yaml) | warning | closed | `stated` / `hedged` / `unclear` |

`relation_nature` 的 `source.quote_zh` 直接记下动机：*「抽取阶段须明确区分知识间的因果关系与相关性；只有因果关系才能直接指导实验」*。`relation_assertion_mode` 记：*「文献已包含大量因果表达；抽取须保留原文的语气，不得把推测写成断言」*。

### 2.4 两个新字段

```yaml
transform.relation_nature:
  type: string
  availability: N          # 编译期派生
  vocabulary: relation_nature
  definition_zh: 关系的语义性质（因果、相关、结构、描述或未知）；由 predicate_label 词表的值属性 nature
                 在契约编译期派生，不由抽取模型判断
  key_role: relation       # serves: derivation, topic2   argument_role: warrant
  since: 3.6.0

transform.relation_assertion_mode:
  type: string
  availability: D          # 直接抽取
  vocabulary: relation_assertion_mode
  definition_zh: 原文对该关系的断言方式（明确陈述、限定表述或无法判断）；记录原文的语气，不记录关系真假
  key_role: relation       # serves: derivation, topic2   argument_role: qualifier
  since: 3.6.0
```

`transform.relation_evidence_type`（I）**不改动**，仍表示依据类型。

### 2.5 两条新规则（warning，推断）

| 规则 | 触发条件 | 要求 | 佐证 |
| --- | --- | --- | --- |
| **R036** | `relation_nature == associational` **且** `relation_assertion_mode == stated` | 需要 `agent.supporting_evidence` 或 `transform.relation_evidence_type` 之一 | 填写原则5：关联证据不能自动升级为因果结论 |
| **R037** | `relation_nature == causal` | 需要 `transform.relation_evidence_type` | 因果性质的关系须说明其依据 |

即：**相关性质被平铺陈述却无证据** → 提示补证据或降级表述；**因果性质缺少依据说明** → 提示补证据类型。两条均为推断级，按 warning 处理。

### 2.6 `bdc derive` 携带性质与语气（`derive_format` 3 → 4）

派生语句、以及对应的 `triples` / `graph` 边，现在都带 **`relation_nature`** 与 **`relation_assertion_mode`**。契约画的因果/相关线因此进入**派生视图**，而不只是留在记录里。

当记录没有人工复核的 `predicate_label` 时，**回退**取 `predicate_code` 命中代码的 `nature`——同一个确定性判断，不是第二种解读。无值时该键**缺席而非 None**，旧契约记录不受影响。

### 2.7 谓词词表扩充（让真实文献命中）

- **新增 7 个代码：**

  | 代码 | 性质 | 说明 |
  | --- | --- | --- |
  | `trait_correlated_with_trait` | associational | 性状–相关–性状 |
  | `qtl_overlaps_qtl` | associational | QTL–重叠–QTL |
  | `locus_decreases_trait` | causal | 位点–降低–性状 |
  | `locus_increases_trait` | causal | 位点–提高–性状 |
  | `locus_regulated_by_gene` | causal | 位点–受基因调控 |
  | `gene_involved_in_process` | causal | 基因–参与–过程 |
  | `cross_omics_regulates` | causal | 跨组学–调控（合并 v2 附录 A-5） |

  代码按**论文实际陈述的主语与宾语**命名：`locus_regulated_by_gene` 以位点为主语、基因为宾语，因为
  “the QTLs … are likely regulated by a single gene” 并没有说明哪个基因调控哪个性状。仓库里没有任何字段的
  实体类型是 `allele`（`common.reference_allele` 等是 `entity_attribute`，不是实体提及），因此以 `allele_`
  开头的代码永远无法命中，改用 `locus_`。

- **扩充线索词**，使真实文献的逐字谓词（`was correlated with` / `increased the` / `decreased the` / `regulated by` / `overlapped with` / `involved in`）能解析到代码。
- **谓词保持方向**（[src/breeding_contract/relations.py](src/breeding_contract/relations.py)）：线索词只在**以自身语态出现**时才算命中。主动线索被用作被动（“plant height was controlled by qPH7.1”“受…调控”）会把性状放到施动端，而端没有类型时已无类型门槛能拦住，因此不再命中。英文以“分词 + by”（中间可有一个副词）判断，中文以动词前的「受 / 被」判断（不含「受体」，也不含「被认为 / 被发现」等）。只修饰宾语的 by（“decreased the transparency values conferred by”）不改变主动语态。被动代码 `locus_regulated_by_gene` 只保留被动线索 `regulated by`，主动的 “A regulates B” 不会命中它。
- **类型门槛只约束“有类型的端”**（[src/breeding_contract/relations.py](src/breeding_contract/relations.py)）：代码声明的 `subject_types` / `object_types` 仅在该端确实带类型时才过滤。端没有类型（论文里一笔带过的 “a single gene”、表里定义的性状缩写）**不构成反证**——主语该被排除，是因为已知其类型不同，而不是因为不知道它是谁。综上，`variety_derived_from` 的主语补上 `population` / `parent`，宾语补上 `population`。

### 2.8 看板：新增「关系」页签 + 所有长页签分页

- **新「关系」页签**（[site/pages/papers.html](site/pages/papers.html)）：逐条列出 主语–谓语–宾语，带 **因果 / 相关 / 结构 / 描述 / 未知** 标签，并可按性质筛选，让读者把「能指导实验的」与「只是共变的」分开。
- **所有长列表分页**：原先只有「抽取记录」分页，关系 / 研究流程 / 语义校验 / 校验与审计 / 运行历史 下的列表会把整页无限拉长。现在每个列表都经共用的分页器分页，且各用自己的页码键，翻动一个列表不会带动另一个。

### 2.9 其他

- **元模式**（[schemas/meta/vocabulary.meta.schema.json](schemas/meta/vocabulary.meta.schema.json)）：接受逐取值的 `nature` 属性与 `merged_v2` 来源。
- **文档**：新增 [docs/relation_semantics.md](docs/relation_semantics.md)（叙述性说明）；[docs/downstream.md](docs/downstream.md)、[docs/versioning.md](docs/versioning.md) 相应更新。
- **测试**：新增 [tests/test_relation_semantics.py](tests/test_relation_semantics.py)；[tests/test_dashboard.py](tests/test_dashboard.py)、[tests/test_source_parts.py](tests/test_source_parts.py) 相应更新。

## 3. 影响与兼容性

- **为什么是 MINOR。** 新增字段（`transform.relation_nature`、`transform.relation_assertion_mode`）、新增词表（`relation_nature`、`relation_assertion_mode`）、新增代码（`predicate_label` 的 7 个 `proposed` 代码）、新增 warning 级规则（R036、R037）。依 [docs/versioning.md](docs/versioning.md)：新增字段 / 代码 / 画像 / warning 级规则属 MINOR。**没有**删除或重命名字段、**没有**收紧任何既有规则为 error。
- **对旧记录的有效性：无影响。** 3.6.0 之前产出的记录按各自声明的版本继续通过校验。新字段均为可选（`required: N`）。
- **默认为空。** 抽取画像只从 `predicate_label`（可用性 I）填 `relation_nature`，因此一次全新运行默认返回空；性质主要靠 `predicate_code` 的确定性回退或人工复核落地（AMB-042）。
- **AMB-024 保持未决。** `agent.causal_direction`、`agent.association_vs_causation` 的取值仍待数据负责人确定，两者保持 **I**，抽取画像不暴露。

## 4. 实测效果（paper_1、3.6.0 重跑）

10 条关系解析为：**结构 1 / 相关 4 / 因果 4 / 未知 1**。逐条如下：

| 谓词原文 | 命中代码 | 性质 |
| --- | --- | --- |
| was developed from a cross between | `variety_derived_from` | 结构 |
| was highly positively correlated with | `trait_correlated_with_trait` | 相关 |
| was highly positively correlated with | `trait_correlated_with_trait` | 相关 |
| was negatively correlated with | `trait_correlated_with_trait` | 相关 |
| overlapped with | `qtl_overlaps_qtl` | 相关 |
| decreased the transparency values conferred by | `locus_decreases_trait` | 因果 |
| decreased the degree of chalkiness conferred by | `locus_decreases_trait` | 因果 |
| are likely regulated by | `locus_regulated_by_gene` | 因果 |
| is directly involved in | `gene_involved_in_process` | 因果 |
| increased | （未命中，保持 `verbatim`） | 未知 |

裸谓词 `increased` 按设计**保持未编码**（线索为 `increased the`），在看板上诚实显示为「未知」。

# 育种文献记录契约 3.5.1 更新说明

**发布日期：** 2026-10-13　|　**版本号：** 3.5.1（PATCH）　|　**契约：** breeding-literature-record　|　**仓库：** atoz03/pdf2jsonl

本次更新只改动抽取画像内部一处检查的范围，不新增、不删除、不重命名任何字段、词汇、代码、规则或画像，也不改变任何类型的含义。3.5.1 之前产出的记录继续按其自身声明的版本通过校验。

---

## 1. 背景 / 动机

对两篇论文做的一次试跑暴露了一个问题：逐字取值核验（`VALUE_NOT_ON_EVIDENCE_PAGE` / `VALUE_NOT_IN_SOURCE`）几乎淹没了复核队列。

- 这次试跑共产生 **191 条警告**；
- 其中 **149 条**来自"论文用自己的话表述"的字段——仅 `agent.finding_text` 一项就有 **99 条**；
- 而这 149 条是 **98 条记录**停留在 `pending_review` 的**唯一**原因。

原因很直接。像 `agent.finding_text` 这类字段，论文本就不会逐字给出同一句话；它定义上就是一条改述（paraphrase）。对改述字段做"逐字出现在证据页上"的检查，报出来的是**写作方式**，而不是**错误**。这正是悬而未决的歧义 **AMB-014**（`finding_text 为原文还是改述`）在检查层面的落点。

3.5.1 把核验限定在"取值是论文事实"的字段上，让检查去报那些**必须逐字出现**的取值（名称、编号、坐标、测量值、统计量），而不是那些**永远不会逐字出现**的措辞。

## 2. 变更内容

### 2.1 新增画像键 `evidence_policy.value_presence_roles`

`profiles/pdf_extraction.yaml` 的 `evidence_policy` 中新增一个键，位于 `value_presence_check`（第 196 行）之后、`value_presence_exempt`（第 202 行）之前：

```yaml
evidence_policy:
  required_for_model_records: true
  verify_quote: true
  page_search_radius: 1
  max_quote_chars: 1200
  value_presence_check: warning
  # Only fields whose value is a fact of the paper (a name, id, coordinate, measurement, statistic) are checked
  # for verbatim presence. Fields the paper states in its own words (assertion, method_spec, condition,
  # interface_spec, study_design) are paraphrases by definition, so the check would flag the writing, not an
  # error — see docs/review.md and AMB-014.
  value_presence_roles: [entity_mention, entity_id, entity_attribute, reference_frame, context_key, measurement, statistic]
  value_presence_exempt: [common.source_language]
```

语义：

- 该键列出的是 **`key_role` 代码**，不是字段路径。只有 `key_role` 落在列表内的字段，其取值才会接受逐字出现性检查（`VALUE_NOT_ON_EVIDENCE_PAGE` / `VALUE_NOT_IN_SOURCE`）。
- **未列入的字段不检查**：论文用自己的话表述的字段、以及所有其它角色，不再产生取值核验警告。
- **省略该键即保持 3.5.0 行为**：每个字段都检查。空列表 `[]` 与省略等价（见 §3）。
- 检查的严重级别（`value_presence_check: warning`）和 `evidence_policy` 的其余部分不变。

**列出的 7 个角色**（契约共 25 个 `key_role` 代码，全部为"论文事实 / 身份事实"类）：

| 角色 | 覆盖的取值举例 |
| --- | --- |
| `entity_mention` | 作物、种质、群体、性状、基因、标记、QTL 的原文名称 |
| `entity_id` | 实体的规范 ID / 登录号 |
| `entity_attribute` | 坐标、类型、等位基因、引物、系谱 |
| `reference_frame` | 坐标或 ID 所依赖的组装 / 注释 / ID 体系 / 本体版本 |
| `context_key` | 研究 / 试验 / 环境 / 样本 / 小区 / 重复的稳定 ID |
| `measurement` | 带单位的原始或归一化测量值与判定结果 |
| `statistic` | LOD、PVE、效应量、p/q 值、指数值 |

**明确不做核验的角色**（评论与 CHANGELOG 中点名的改述类）：`assertion`、`method_spec`、`condition`、`interface_spec`、`study_design`；其余未列入的角色（`appraisal`、`record_link`、`relation`、`entity_alignment`、`corpus_qa`、`derivation_control`、`asset`、`governance`、`lifecycle` 及身份类 `record_identity`、`source_identity`、`bibliographic`、`evidence_locator`）同样不检查。

### 2.2 契约侧的两处配套改动

1. **元模式收录该键**（[schemas/meta/profile.meta.schema.json](schemas/meta/profile.meta.schema.json)）：`evidence_policy` 下新增

   ```json
   "value_presence_roles": {"type": "array", "items": {"type": "string", "pattern": "^[a-z][a-z0-9_]*$"},
                            "uniqueItems": true,
                            "description": "key_role codes whose field values must appear verbatim on the evidence page; fields of other roles are not checked (they are stated in the paper's own words)"}
   ```

   **此处不设 `enum`**：成员资格在编译期校验，而不在模式层。

2. **编译期校验角色成员资格**（[src/breeding_contract/compile.py](src/breeding_contract/compile.py) 的 `resolve_profile`，追加在 `value_presence_exempt` 校验之后）：

   ```python
   for role in (p.get("evidence_policy") or {}).get("value_presence_roles") or []:
       if role not in (contract["codes"].get("key_role") or {}):
           raise ContractError(f"profile {name}: evidence_policy.value_presence_roles names unknown key_role {role!r}")
   ```

   列出的每个角色都必须存在于编译后的 `codes.key_role` 表中，否则画像解析失败。

### 2.3 管线按角色过滤

[skills/pdf2jsonl/scripts/pdf2jsonl_skill/pipeline.py](skills/pdf2jsonl/scripts/pdf2jsonl_skill/pipeline.py)：

```python
# Assembler.__init__  —— None 表示"检查每个字段"
roles = self.policy.get("value_presence_roles")
self.presence_roles = set(roles) if roles else None
```

```python
# Assembler.value_warnings 的逐字段循环
f = self.fields.get(path, {})
if path in self.exempt or f.get("vocabulary"):
    continue
if self.presence_roles is not None and f.get("key_role") not in self.presence_roles:
    continue          # 新增：非取值承载角色不进入逐字存在性检查
code = self._present(value, pages, index)
```

`_present` 本身、`value_presence_check` 的严重级别、以及调用点（`asm.value_warnings(...)`）均未改动。

### 2.4 看板：把语义校验收进工作流

3.5.0 引入了语义校验（`bdc verify tasks|apply`），但看板并不知道它的存在——它只按记录文件自身的状态展示一次运行，校验产物（`<stem>.verification.json`、`<stem>.verified.jsonl`）不进页面。3.5.1 把校验接进了看板的工作流。改动全部集中在 [scripts/make_dashboard.py](scripts/make_dashboard.py)（+159 行）与 [site/dashboard.template.html](site/dashboard.template.html)（测试见 [tests/test_dashboard.py](tests/test_dashboard.py)）。

**（1）引导弹窗从三步变四步，插入语义校验。**

看板右上角"添加论文与更新看板"的引导（3.5.0：1 将 PDF 放入仓库 → 2 运行抽取流程 → 3 重新生成，然后刷新页面）在 3.5.1 成为四步，`make dashboard` 顺延为第四步：

- 1 将 PDF 放入仓库（补充说明 **补充材料 / `--supplement`**）
- 2 运行抽取流程
- **3（可选）运行语义校验** —— `bdc verify tasks out/paper.jsonl --out review/ && bdc verify apply out/paper.jsonl --verdicts review/paper.verify.verdicts.json --out review/`
- 4 重新生成，然后刷新页面 —— `make dashboard`

即看板刷新现在默认发生在语义校验**之后**，校验的 `--out review/` 产物与记录同处一次运行。

**（2）看板读取校验报告。**

`make_dashboard.py` 新增 `_verification()`：当 `<stem>.verification.json`（和 `<stem>.verified.jsonl`）位于某次运行的记录**旁边**、或其**旁边的 `review/` 目录**时（即上一步的产物位置），页面就读取它，把该次运行按**校验后状态**展示，并列出 findings、冲突候选、遗漏候选，报告与已核验记录均可下载。它只展示、不改动任何记录。同时校验完整性：已核验记录的 `sha256` 若与报告不一致，页面显式提示。

**（3）明细弹窗新增"研究流程""语义校验"两个标签。**

一次运行的明细标签由 `[抽取记录, 原文与证据, 校验与审计, 运行历史, 导出文件]` 变为
`[抽取记录, **研究流程**, 原文与证据, **语义校验**, 校验与审计, 运行历史, 导出文件]`。"研究流程"渲染派生的 workflow 视图（无则给出"需要契约 3.5.0 与 `statement_role`"的空状态），"语义校验"展示校验 findings。

**（4）记录警告按"家族"分组，并标注可比性。**

每次运行的记录校验警告归入若干"家族"，可按家族筛选：

| 家族 | 覆盖的代码前缀 |
| --- | --- |
| 取值核验 | `VALUE_`、`DOCUMENT_VALUE_`、`EVIDENCE_PAGE_CORRECTED`、`EVIDENCE_TABLE_NOT_ON_PAGE`、`EVIDENCE_CELL_KEY_NOT_ON_PAGE` |
| 填写规则 | `RULE_` |
| 记录链接 | `CANDIDATE_LINK_`、`UNRESOLVED_LINK`、`LINK_` |
| 来源完整性 | `SOURCE_PART_` |
| 输出完整性 | `OUTPUT_INTEGRITY` |

取值家族同时标注本次运行是**按 `key_role` 选择性检查**，还是**检查了每个字段**（无 `value_presence_roles` 的运行，或 3.5.1 之前的运行），提示前者的取值警告数与后者不可直接比较。

**（5）文档。**

- [docs/review.md](docs/review.md)：Layer 1 的 Evidence 条目改写为"只检查取值是论文事实的字段（`evidence_policy.value_presence_roles` 列出的 `key_role`）；改述字段按定义就是改述，警告只会指向写作而非错误（AMB-014）"；并新增一段说明看板如何读取校验报告、如何按家族分组、如何标注可比性。
- [README.md](README.md)：论文看板一行补充"研究流程、语义校验"与"校验提示按取值核验 / 填写规则 / 记录链接 / 来源完整性分组并可逐条筛选"。

## 3. 影响与兼容性

- **为什么是 PATCH 而不是 MINOR。** 没有字段、组、词汇、代码、记录类型、规则或画像被新增 / 删除 / 重命名；没有类型、可用性或含义变化；`value_presence_check` 仍为 `warning`，未提升为 `error`；没有任何约束被新增或收紧。这是一处**画像内部改动**（角色与填写规则）。[docs/versioning.md](docs/versioning.md) 的语义化版本表把"措辞 / 来源引用 / 歧义说明 / 文档"归为 PATCH，并明确说明**画像内部改动（角色、填写规则）无法机械检测、需人工复核**；本改动正是这一类。让检查"更精准"（报更少假警报）是朝收紧真正有意义的判定方向移动，而不是放松约束。

- **对记录有效性的影响：无。** 该键只影响**警告的产生范围**，不改变记录的通过 / 拒绝判定，也不改变 `review_status` 的判定逻辑。3.5.1 之前产出的记录、以及不带该键运行的记录，行为与 3.5.0 完全一致。

- **可比性边界。** 取值核验警告数只在**同一 `value_presence_roles` 设定**下可比。一个不带该键（即"检查每个字段"）的运行，其取值警告数不能与之后的运行直接比较。看板已对此显式标注。

- **两处需要留意的实现细节（供画像作者与复核者）：**
  1. **文档级检查不受该键约束。** `check_document`（`DOCUMENT_VALUE_NOT_IN_SOURCE`）仍对每个显式、非豁免、非词汇的**文档级字段**做逐字检查，不论其 `key_role`。因此"检查现在只对列出的 `key_role` 字段运行"严格来说只覆盖**逐条候选记录级别**的 `value_warnings`，不含文档级检查。
  2. **空列表 `[]` 等价于省略键**（`set(roles) if roles else None`），即"检查每个字段"；元模式允许 `[]`（无 `minItems`）。画像无法用该列表表达"什么都不检查"——要表达这一点应使用 `value_presence_check: off`。

## 5. 未变更的内容

- **字段目录**：412 个字段及其定义、类型、`key_role`、`serves`、功能标签、来源——全部未动。
- **词汇与代码**：所有受控词表、25 个 `key_role` 代码、`review_status` 代码——未增删改。

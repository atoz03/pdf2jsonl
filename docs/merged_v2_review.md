# merged.zip 合并评估与落地记录

[返回 README](../README.md) · [字段定义与示例](../FIELD_DEFINITIONS.md) · [迁移使用说明](migration.md)

本次已把压缩包作为第四套输入来源接入仓库：补齐三个样本字段，增加 merged v2 数据迁移入口，
并保留全部原始材料和未转换内容。规范版本为 **3.3.0**，共 **400 个字段**；原有 397 个字段的定义保持一致。

## 原包是什么

`merged.zip` 含 7 个文件：README、字段说明、JSON Schema、空模板、JSON/JSONL 示例及三套来源的映射说明。
文件原样存于 [sources/merged_v2](../sources/merged_v2/)，压缩包保存在
[sources/archives/merged_v2__merged.zip](../sources/archives/merged_v2__merged.zip)，逐文件 SHA-256 见
[来源清单](../sources/SOURCES.md)。JSON 与 JSONL 示例的内容相同，均为合成论文。

它沿用了仓库已吸收的 cyx/legacy、lyy/v3 和 d/omics 三套设计。源 Schema 展开后共有 **1,022 个叶路径**，
较 legacy v1 有 317 个新增路径。这个数量包含实体、证据和观测对象中重复出现的属性，不能直接与仓库的逻辑字段数比较。

## 吸收了哪些内容

| 内容 | 原仓库情况 | 本次落地 |
|---|---|---|
| 生物学重复与技术重复 | 只有含义不区分的 `common.replicate_id` | 新增 `common.biological_replicate_id`、`common.technical_replicate_id`；保留来源编号，不推断类别 |
| 采样时间 | 已有测量时间和相对采样时间，缺少独立的采样时刻原文 | 新增 `common.sampling_time`，与 `observation_time` 分开 |
| 文档内观测数组 | 具备原子观测字段，尚无 merged 输入转换 | 新增 `bdc migrate merged`，拆出表型、环境、基因型和组学观测 |
| 样本—测定—观测关联 | 字段齐备，缺少此来源的引用解析 | 按 `sample_ref` / `assay_ref` 关联样本、组织、重复、文库和平台；检查重复 ID、冲突值及样本归属 |
| 大文件资产 | 具备资产字段，尚无 merged 数组转换 | 将 `assets[]` 转成资产清单，严格校验摘要、类型和现有约束 |
| 细粒度溯源 | 现有页码、表图、行列键、引文可复用 | 观测使用自身证据，显式换算出版页；段落编号不冒充表图编号 |
| 合并映射可审计性 | 只有 legacy / omics 映射 | 新增 [merged 映射](../mappings/merged_to_current.yaml)，覆盖全部 1,022 个源叶路径，并区分迁移、控制与保留状态 |

三个新字段均为 **可选、直接抽取（D）、provisional**，来源及边界登记为 `AMB-037`。
它们自动进入 PDF 抽取画像、Schema、字段说明和 JSON 示例；旧版本仍按原有发布文件校验。

## 发现的源数据问题及处理

| 检查结果 | 影响 | 处理方式 |
|---|---|---|
| 原示例通过源 Schema；空模板产生 56 个错误 | 空模板的占位值不能直接当有效记录 | 原样保留模板；迁移先检查源 Schema，再检查目标契约 |
| `source_locations` 和各类证据含 2221–2234 等出版页码 | 不能直接作为 PDF 物理页 | 示例显式使用 `--page-offset 2220`；不提供偏移时不填物理页 |
| 部分原文片段含 `...`；`sec-result` 没有文档章节定义 | 可用性和引用完整性不足 | 不完整引文不写入 `source_quote`；悬空章节标记复核；所有迁移引文均待 PDF 核验 |
| 两条资产摘要为 `f6e0ba80c14e...`、`7c3d...` | 不是合法 SHA-256 | 拒绝这两条资产候选，保留原值和错误原因 |
| 观测时间使用 `+08:00` | 目标 `observation_time` 要求 UTC | 对明确时区作确定性换算；不猜测无时区字符串的时区 |
| `omics_feature` 为开放对象；示例 `go_term` 是数组 | 目标字段可能是标量，未知键也可混入 | 单元素数组可解包；多值和未知键进入残留，保留原貌 |
| 源统计值缺少部分范围约束 | 源 Schema 通过仍可能含无效概率或剂量 | 继续执行仓库概率范围、倍性、互斥及数据集规则 |
| 文档级位置、推理信息、QA/图谱引用与原子事实未逐条绑定 | 广播或直接复制会错配证据 | 使用原子事实路由；其他值保存在残留中，等待明确绑定与 ID 重写 |
| 原 README 声称 v1 天然兼容；实际旧示例不能直接通过新 Schema | 输入版本不能靠文件名判断 | 明确区分来源版本与仓库版本，迁移时校验 `v2.0.0` |

源 Schema 还允许 `observations: []` 的单位行，且没有完整的跨字段校验。因此它通过校验只说明满足该来源的结构要求。

## 已验证的转换结果

```bash
bdc migrate merged sources/merged_v2/breeding_jsonl_example_v2.json \
  --out out/merged --page-offset 2220
```

该合成示例得到 **18 条通过目标校验的原子记录**：已有事实路由转换的 13 条、四类观测各 1 条、组学资产 1 条。
**14 个候选被拒绝**：两条资产的摘要截断，以及既有事实路由中证据不足或数值无效的 12 个候选。
输出记录均标记 `pending_review`；这个结果不代表已验证原论文真实性或证据引文。

输出的 `.migration.json` 给出合同版本、来源哈希、映射哈希、来源实例和原始条目 ID。
`.residue.json` 保留每个未转换的非空源值；`.migrated.errors.jsonl` 保存拒绝原因和候选。
可运行的结果见 [examples/migration/merged_v2](../examples/migration/merged_v2/)。

回归检查覆盖：原文件哈希、1,022 个源路径的映射覆盖、源值去向、样本/测定关联、重复引用、冲突值、
出版页换算、UTC 转换、无时区时间、概率/剂量约束、多值保留、重排后的稳定 ID、父文档前后顺序、
重复记录、运行输出格式，以及新增字段与旧版 397 个字段的一致性。

## 本次保留的边界

原包的文档主记录可以通过导入转换，仓库继续以稀疏原子记录作为正式数据格式，文档聚合仍由 `bdc bundle` 提供。
跨文献置信评分、智能体运行状态、技能注册状态、翻译和向量没有与论文事实混写；内容完整保存在源文件及残留中。
独立的 `transform` 和运行时 `tool_spec` 单位行会明确报告尚未支持。

后续有价值的补充是：为 QA/图谱引用提供 ID 重写、给文档级推理绑定逐条证据，以及补齐病虫害等实体的独立来源定义。
这些需要进一步确认关联语义；当前资料不足以自动完成。批量父文档解析目前在内存中进行，大规模数据应分成有界批次。
